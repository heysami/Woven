# Component DS format (v1)

The contract between a component design system's files and Woven's tooling (`editor/tools/ds/`). Anyone authoring a component DS writes to this spec. The overall design is in [component-design-system.md](component-design-system.md).

## Folder

```
design-systems/<id>/
  meta.json
  tokens/tokens.css            :root custom properties only
  foundations/*.css            element base styles, typography roles, utilities
  components/<name>/           a block (layer: layout | atom | molecule | organism)
  patterns/<name>/             a block (layer: pattern)
  shells/<name>/               a block (layer: shell)
  services/<name>.js           shared functions on the DS namespace
  icons/<style>/<name>.svg     icon sources, one per file (style = filled | outline | ...)
  themes/<theme>.css           token overrides scoped to [data-theme="<theme>"]
  assets/                      fonts, images
  DESIGN.md                    principles plus rules that cannot be code
  build/                       GENERATED by build_ds.py, never hand-edited
    ds.css                     every CSS file, layered
    ds-runtime.js              runtime + all templates, schemas, behaviors, services, icons
    manifest.json              machine-readable catalog
    CATALOG.md                 one line per block (what agents read)
    gallery.html               every block's examples, rendered by the runtime
```

`meta.json` adds:

```json
{
  "kind": "component",
  "componentFormat": 1,
  "files": {
    "bundle": "build/ds.css",
    "runtime": "build/ds-runtime.js",
    "catalog": "build/CATALOG.md",
    "gallery": "build/gallery.html",
    "designMd": "DESIGN.md"
  }
}
```

## A block

Block names are `[a-z][a-z0-9-]*`, unique across `components/`, `patterns/` and `shells/`. The tag is `ds-<name>`. `custom` and `slot` are reserved.

```
components/<name>/
  component.json   required
  template.html    required
  style.css        optional, token variables only
  behavior.js      optional
  examples.json    required (at least one example)
```

### component.json

```json
{
  "name": "filter-chip",
  "title": "Filter chip",
  "layer": "atom",
  "oneLine": "Table and search filter trigger.",
  "useWhen": "Any filter on a table, list or search result.",
  "notForUseWhen": "Form fields that submit a value: use ds-select.",
  "replaces": ["select"],
  "rootClass": "filter-chip",
  "props": {
    "label":    { "type": "string", "required": true },
    "count":    { "type": "number" },
    "open":     { "type": "boolean" },
    "options":  { "type": "list" },
    "items":    { "type": "json" },
    "size":     { "type": "enum", "values": ["m", "s"], "default": "m" }
  },
  "slots": {
    "default": { "accepts": "any" },
    "actions": { "accepts": ["button", "link"] }
  },
  "contains": ["icon"],
  "events": ["ds:change"],
  "states": ["is-open", "is-disabled"],
  "copy": { "label": { "maxWords": 3 } }
}
```

| Field | Meaning |
|---|---|
| `layer` | `layout`, `atom`, `molecule`, `organism`, `pattern`, `shell`. Decides the CSS layer. |
| `replaces` | Raw HTML tags this block owns. A PAGE using one of them outside a block or `ds-custom` fails the check. Block templates are DS code and may use any raw element (a filter chip's root can be a `<button>`). |
| `rootClass` | The DS class on the template root. An element carrying it without `data-ds` is hand-built (runtime self-check). Defaults to the first class on the template root. |
| `props` | Types: `string`, `number`, `boolean`, `enum` (needs `values`), `list` (comma-separated in HTML, array in JS), `json` (JSON in HTML, any value in JS). Optional `required`, `default`, `desc`. |
| `slots` | `accepts`: `"any"`, `"text"` (text and inline markup only), or a list of block names. No `slots` key means the block takes no children. |
| `contains` | Blocks the template itself uses. Used for dependency order and CSS ownership. |
| `events` | Custom events the behavior dispatches (all prefixed `ds:`). |
| `states` | Runtime state classes the behavior toggles. Never persisted. |
| `copy` | Content rules per prop: `maxWords`, `maxChars`, `case` (`title`, `sentence`). |

Unknown fields are an error, so typos surface.

### template.html

Exactly **one root element**. The syntax is a small logic-less subset:

| Syntax | Meaning |
|---|---|
| `{{prop}}` | HTML-escaped value. No raw-HTML form exists; markup goes through slots. |
| `{{#if prop}}...{{else}}...{{/if}}` | Truthy: non-empty string or list, `true`, a non-zero number. |
| `{{#if prop == "value"}}` | Equality with a string literal. `!=` also works. |
| `{{#each list as item}}...{{item}} {{item.key}} {{@index}}...{{/each}}` | Loop over a `list` or `json` array. |
| `<ds-slot name="actions">fallback</ds-slot>` | Slot point. `<ds-slot></ds-slot>` is the default slot. Its content is the fallback when nothing is slotted. |
| `{{icon name style}}` / `{{iconViewBox name style}}` | The inner SVG markup / viewBox of an icon from `icons/`. Arguments are prop names or `"literals"`; `style` is optional (default from `meta.defaultIconStyle`, else `filled`). A bare `{{icon}}` is just the prop named `icon`. |
| `<ds-icon name="{{icon}}">` | Other blocks are used as tags. A template never hand-writes another block's markup. |

Variant classes are written inline: `class="filter-chip filter-chip--{{size}}"`.

## Using blocks in a page

```html
<link rel="stylesheet" href="../../design-systems/<id>/build/ds.css">
<script src="../../design-systems/<id>/build/ds-runtime.js"></script>
```

Load the runtime as a plain blocking script in `<head>`.

Static markup:

```html
<ds-filter-chip label="Status" options="Pending,Approved" id="f-status" data-step="2">
  <ds-button slot="actions" variant="text">Clear</ds-button>
</ds-filter-chip>
```

From JS (returns fully expanded markup, synchronously):

```js
el.innerHTML = DS.html("filter-chip", { label: "Status", options: ["Pending", "Approved"] },
                       { actions: DS.html("button", { variant: "text" }, "Clear") });
DS.expand(el);   // only needed if you inserted raw <ds-*> tags and query them right away
```

Raw HTML that is genuinely not in the DS:

```html
<ds-custom reason="one-off approval timeline, no DS block yet"> ... </ds-custom>
```

### Attributes on a block tag

- **Declared props** become template values. A block may declare a prop whose name is also a passthrough name (`title`, `style`, `role`, `hidden`, `tabindex`); on that block it is a prop. `id`, `class`, `slot`, `data-*` and `aria-*` are reserved and can never be props.
- **Passthrough attributes** (`id`, `class`, `data-*`, `aria-*`, `hidden`, `title`, `role`, `tabindex`) are copied onto the root. `class` is appended, and it is for page placement only: page CSS must never restyle a DS class.
- **`slot="name"`** on a child sends it to that slot.
- **Anything else** fails the check, and the runtime warns about it in the console.

### What the runtime produces

The tag is **replaced** by the template's root element. No wrapper element remains.

```html
<button class="filter-chip filter-chip--m" id="f-status" data-step="2"
        data-ds="filter-chip" data-ds-props='{"label":"Status","options":["Pending","Approved"]}'>
  ...
  <!--ds-slot:actions--><button class="btn btn--text" data-ds="button" ...>Clear</button><!--/ds-slot-->
</button>
```

- `data-ds` names the block. `data-ds-props` holds the props that were set explicitly.
- Slotted content sits between `<!--ds-slot:name-->` and `<!--/ds-slot-->` comments. Comments do not affect CSS selectors.
- `ds-custom` becomes `<!--ds-custom reason="..."-->...<!--/ds-custom-->` around its raw content.
- Expansion is outer-first. Slotted nodes are moved, not cloned, so page JS references made before expansion survive.

### Timing

- **Static markup:** the page is hidden from the runtime's load until `DOMContentLoaded`. Then every `<ds-*>` is expanded and the page is shown.
- **After load:** a MutationObserver expands any `<ds-*>` inserted later. It runs as a microtask, so before paint.
- **Page JS that queries right after inserting markup** must use `DS.html()`, which returns expanded markup, or call `DS.expand(el)`.

### Saving back (editor)

`DS.serialize(root)` returns source-form HTML. Each `data-ds` element turns back into its `<ds-*>` tag: props come from `data-ds-props`, passthrough attributes come from the live element, and runtime state classes (`is-*`, `has-*`, `js-*`) are dropped. Slots come back from the comment markers. The editor's save-back paths call this whenever `window.DS` exists. Persistent state (which tab is active) must be a prop, never a class.

## behavior.js

The body runs with `DS` in scope. The generator wraps it.

```js
DS.behavior("filter-chip", {
  // delegated listeners on document, registered once, survive any re-render
  on: {
    "click": function (e, root) { root.classList.toggle("is-open"); DS.emit(root, "ds:change", { open: root.classList.contains("is-open") }); }
  },
  // optional, called once per expanded instance (e.g. third-party setup)
  init: function (root, props) {}
});
```

Runtime-only state is never saved back to the page source: state classes (`is-*`, `has-*`, `js-*`), `aria-expanded|selected|pressed|checked`, and any `data-ds-*` attribute. A behavior that needs to mark an element at runtime uses one of those, never a plain `data-*` attribute (that would be saved as authored markup).

Handler keys are `"<event>"`, which matches inside the block root, or `"<event> <selector>"`, which matches a descendant. `root` is the closest `[data-ds="<name>"]`. Blocks talk to each other through attributes (`for="grid-id"`) and `ds:*` events, never by reaching into another block's markup.

## services/<name>.js

```js
DS.service("toast", function (DS) {
  return { show: function (message, opts) { ... } };
});
// used as DS.toast.show("Saved", { variant: "success" })
```

Built-ins provided by the runtime itself: `DS.html`, `DS.expand`, `DS.serialize`, `DS.emit`, `DS.icon(name, { style, size })` (from `icons/`), `DS.props(root)`, `DS.update(root, newProps)` (re-render one instance in place), `DS.manifest`.

## CSS

`build/ds.css` declares:

```css
@layer tokens, base, layout, atoms, molecules, organisms, patterns, shells, themes;
```

- `tokens/tokens.css` goes in `tokens`, `foundations/*` in `base`, each block's `style.css` in the layer for its `layer` field, and `themes/*` in `themes`.
- Inside a layer, files are ordered by `contains` dependencies, then by name. Rule order inside a file is kept.
- A rule where a parent styles a child (`.modal__actions .btn`) belongs in the **parent's** `style.css`, and the parent lists the child in `contains`.
- Page CSS is unlayered, so it beats every DS layer. That is why the checker forbids page CSS from touching DS classes.

## examples.json

```json
[
  { "title": "Default", "props": { "label": "Status" } },
  { "title": "With count", "props": { "label": "Owner", "count": 3 } },
  { "title": "With action", "props": { "label": "Status" }, "slots": { "actions": "<ds-button variant=\"text\">Clear</ds-button>" } }
]
```

The gallery renders every example. Each block needs at least one, and every enum value should appear in some example. Optional fields: `attrs` (passthrough attributes such as `id`), `frame` (`{"height": 480}` renders the example in an iframe, for shells and full-page patterns), `desc`.

## Checks (`ds_check.py`)

`python3 editor/tools/ds/ds_check.py --ds-dir <design-systems/id> (--page <file.html> | --ds-only) [--json]`

| Code | Level | Where |
|---|---|---|
| `unknown-block` | error | page, template |
| `unknown-prop`, `bad-prop-type`, `bad-enum`, `missing-required` | error | page, template |
| `slot-not-allowed`, `no-slots` | error | page, template |
| `raw-replaced-element` (a raw tag that a block `replaces`, outside a block or `ds-custom`) | error | page |
| `hand-built-block` (a block's `rootClass` used on raw markup) | error | page, template |
| `page-css-touches-ds` (page `<style>` or linked local CSS selecting a DS class) | error | page |
| `inline-style-on-block` | error | page |
| `custom-without-reason` | error | page |
| `ds-custom` present | info | page |
| `copy-rule` | warn | page |
| `schema-invalid`, `template-not-single-root`, `missing-example`, `duplicate-block-name`, `token-undefined`, `raw-value-in-block-css` | error | DS |

Exit codes: 0 clean, 1 errors, 2 not a component DS.
