# Subagent 1.V.3d - Asset drawer (medium: three.js 3D scene)

You own **ONE asset** of medium `3d` - an interactive or ambient 3D scene rendered with three.js. **Pathway B**: you write the scene code directly.

**Read [`../conventions.md`](../conventions.md) before starting.**

## Input (envelope only)

See [`1V-visual-orchestrator.md`](1V-visual-orchestrator.md) §Step 5.

```
pipeline=["prompt","three-skill"]
nodeIds: { prompt, skill, asset }
```

Slot is typically `<canvas data-three="…">` or `<div data-three="…">`.

**You ship the runtime, not just the scene.** There is NO host that creates `scene` / `camera` / `renderer` / `THREE` / `__animate` in a built prototype - those globals exist ONLY inside the editor app, never in the page a user opens. A prototype "opens by double-clicking" (`file://`), so the mount cannot `fetch()` + eval an external `.js` either, and three.js must load from a CDN via an ESM `importmap`. Therefore the scene is DEAD unless YOUR `slotEditDiff` inlines a self-contained mount: the `<canvas>` + an `importmap` (once per page) + an inline `<script type="module">` that imports three, creates its OWN renderer / scene / camera, builds the scene, and runs its OWN rAF loop. Self-contained per slot is the contract - do not rely on host globals, and do not fight the page's existing scripts.

## Output

```json
{
  "assetId": "<id>",
  "promptText": "<1-sentence design intent>",
  "skillCode": "<full three.js scene code as a single string>",
  "params": {
    "outputPath": "<slot.outputPath e.g. assets/three/hero-scene.js>",
    "interaction": "ambient" | "orbit" | "scroll",
    "performance": "background" | "hero"
  },
  "slotEditDiff": "<REQUIRED - the self-contained canvas + importmap + inline module mount (see §6)>"
}
```

`skillCode` (the scene body at `outputPath`) is the editable source-of-truth the editor + re-runs read. But it is NOT what makes the page work - `slotEditDiff` is, because it inlines that scene into a self-mounting module. `slotEditDiff` is REQUIRED for this medium; a `3d` asset with `slotEditDiff: null` ships a dead canvas and fails self-audit.

## Recipe

### 1. Read slot + genre

Same start as the other drawers. 3D is heavy decoration - typically only Marketing / Bento / Apple-style genres allow it. Return `error: "genre forbids 3d medium"` if mismatched.

### 2. Scene template

Author a self-contained ESM module. YOU import three, create the renderer bound to the slot canvas, build the scene, and run your own rAF. `skillCode` at `outputPath` holds this body; §6 shows how the same body is inlined into the shipped page.

```js
import * as THREE from 'three';

const cvs = document.querySelector('[data-three="hero-scene"]');
const renderer = new THREE.WebGLRenderer({ canvas: cvs, antialias: true, alpha: true });
const scene  = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(50, 1, 0.1, 100);
function size(){ const r = cvs.getBoundingClientRect(); renderer.setPixelRatio(devicePixelRatio); renderer.setSize(r.width, r.height, false); camera.aspect = r.width/r.height; camera.updateProjectionMatrix(); }
addEventListener('resize', size); size();

// ---- Lights ----
const ambient = new THREE.AmbientLight(0xffffff, 0.4);
const key     = new THREE.DirectionalLight(0xffffff, 0.8);
key.position.set(2, 3, 2);
scene.add(ambient, key);

// ---- Geometry ----
const geo = new THREE.IcosahedronGeometry(1.2, 1);
const mat = new THREE.MeshStandardMaterial({
  color: 0x445588,             // anchor to --accent
  roughness: 0.4,
  metalness: 0.1,
  flatShading: true
});
const mesh = new THREE.Mesh(geo, mat);
scene.add(mesh);

// ---- Camera ----
camera.position.set(0, 0, 4);

// ---- Own rAF loop ----
const reduce = matchMedia('(prefers-reduced-motion:reduce)').matches;
let vis = true;
document.addEventListener('visibilitychange', () => { vis = !document.hidden; });
function frame(now){
  requestAnimationFrame(frame);
  if (!vis) return;
  const t = reduce ? 0 : now;
  mesh.rotation.x = t * 0.0005;
  mesh.rotation.y = t * 0.0007;
  renderer.render(scene, camera);
}
requestAnimationFrame(frame);
```

### 3. Interaction modes

| Mode | Behavior | When |
|---|---|---|
| `ambient` | Auto-rotate / drift / loop. No user input handlers. | Background decoration. |
| `orbit` | Drag-to-orbit, scroll-to-zoom via `OrbitControls`. | Hero product visualisation. |
| `scroll` | Camera or object animates with page scroll position via `IntersectionObserver` or `scrollY` listener. | Bento / marketing scrolling sections. |

For `orbit`, import `OrbitControls` from the addons path the importmap provides: `import { OrbitControls } from 'three/addons/controls/OrbitControls.js'`. No host runtime, no extra `<script src>` - the `three/addons/` importmap entry (see §6) resolves it.

### 4. Performance budget

| Performance | Constraints |
|---|---|
| `background` | ≤500 triangles total, no shadows, no post-processing, single light, no morph targets. |
| `hero` | Up to ~5000 triangles, optional one shadow-casting light, may use `EffectComposer` for one pass. |

Mobile is the floor - don't ship 60fps-on-M1-only scenes. If the brief demands a heavy scene, mark `performance: hero` and add `if (window.innerWidth < 768) return;` (skip mount on small screens) to your scaffolding.

### 5. Palette - anchor to tokens

Same as shader medium: read `:root` tokens and bake colors into the material:

```js
const mat = new THREE.MeshStandardMaterial({
  color: 0x445588,    // --accent in hex
  emissive: 0x000000,
  roughness: 0.4
});
```

three.js doesn't have a clean way to consume CSS variables; baking is the standard approach.

### 6. Output file + self-contained mount (REQUIRED)

Two writes, both mandatory:

**(a) The editable source.** Write the scene module body to `slot.outputPath` (e.g. `assets/three/hero-scene.js`). This is what the editor's asset-controls and a re-run read. It does NOT run on its own.

**(b) The self-contained mount.** Emit a `slotEditDiff` that replaces the slot with a `<canvas data-three="…">`, ensures the page has ONE ESM `importmap` for three (add it in `<head>` if absent; do NOT duplicate if another 3d slot already added it), and inlines the SAME scene body inside a `<script type="module">`. Nothing fetched, nothing global.

```jsonc
"slotEditDiff": {
  "file": "<slot.file>",
  "find": "<div class=\"hero-3d\"></div>",
  "replace": "<canvas class=\"hero-3d\" data-three=\"hero-scene\"></canvas>\n<script type=\"module\">\n// <PASTE THE EXACT SCENE MODULE BODY FROM outputPath HERE - it already imports three, makes its own renderer/scene/camera, and runs its own rAF>\n</script>"
}
```

And, once per page, in `<head>` (skip if already present from another 3d slot):

```html
<script type="importmap">
{ "imports": {
  "three": "https://unpkg.com/three@0.178.0/build/three.module.js",
  "three/addons/": "https://unpkg.com/three@0.178.0/examples/jsm/"
} }
</script>
```

Pin the SAME three version the project already uses elsewhere (grep for an existing `three@` importmap first). `OrbitControls` / other addons import from `three/addons/…` - the addons path in the importmap makes that resolve with no extra `<script src>`.

## Self-audit

- [ ] Genre allows 3D (Marketing / Bento / Apple-style). Otherwise returned `error`.
- [ ] `slotEditDiff` inlines a self-contained `<canvas>` + `<script type="module">` (scene body pasted in) + a `<head>` `importmap` for three (added once, not duplicated) - NOT a `data-three` attribute pointing at an external runtime that does not ship. The page must render when opened directly via `file://` (three loads from CDN via importmap; no `fetch` of local `.js`, no host globals).
- [ ] The inlined scene body is byte-identical to what I wrote at `outputPath` (no drift).
- [ ] Scene imports three via the importmap (`import * as THREE from 'three'`) and creates its OWN renderer / scene / camera - it does NOT assume host-provided `THREE` / `scene` / `camera` / `renderer`.
- [ ] Material colors are anchored to `--accent` / `--surface` from tokens.
- [ ] At most one directional light unless `performance: hero`.
- [ ] Scene runs its OWN `requestAnimationFrame` loop (renders + pauses on `visibilitychange`, freezes under `prefers-reduced-motion`); no reliance on a host `__animate`.
- [ ] Mobile gate present if scene is heavy (`performance: hero` + `window.innerWidth < 768` skip).
- [ ] No `OrbitControls` reference unless the runtime confirmed support.
- [ ] Adjustable controls exposed via the asset-controls shim (orbit/rotation speed, a key material color, camera distance, light intensity - 3-6 knobs), per `../asset-controls-contract.md`. Each `apply(v)` drives a scene handle / loop variable.

## Don't

- Don't assume a host-provided `THREE` global or `scene` / `camera` / `renderer` / `__animate`. None of that ships in a built prototype. Import three via the page importmap and create your own - the scene must be self-contained.
- Don't add a new external `<script src="…three…">`. three loads via the ESM `importmap` you add to `<head>`; addons resolve through the `three/addons/` map entry.
- Don't ship a hero rotating cube. A cube IS the AI-tell for "generic three.js scene." Pick a domain-specific subject - a packaging mock, an architectural section, a particle field around a logo, a faceted icosahedron with brand tint. If you can only think of a cube, return `error: "no scene concept fits the brief"`.
- Don't load textures from the network. The brief's identity comes from form and light, not surface detail.
- Don't add post-processing (bloom, SSAO, depth-of-field) unless `performance: hero` and the brief explicitly calls for it.
