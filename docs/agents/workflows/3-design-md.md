# Workflow 3 - Generate `DESIGN.md` for a design system

**Triggers:** Workflow 0 (DS build) just finished writing `styles.css` + `gallery.html` for a DS; Workflow 6b (DS update) just applied accepted proposals and needs the prose refreshed; user clicked "Export DESIGN.md" against a DS library node.

`DESIGN.md` is **per design system**, not per branch. Output lives at `design-systems/<id>/DESIGN.md` - inside the DS library node, not at project root. Exploration branches that share main's DS share its `DESIGN.md`.

## Inputs (single source of truth)

`DESIGN.md` is **derived from** the DS library node:

1. **`design-systems/<id>/styles.css`** - for the `tokens` half (`:root` block → colors / typography / radii / shadows / spacing).
2. **`design-systems/<id>/gallery.html`** - for the `components` half. Every primitive variant lives here in idle state (see PROTOTYPE.md §12). The gallery's `<section class="ds-section">` blocks define the YAML `components` map.
3. **`design-systems/<id>/meta.json`** - for `name`, `description`, `genre`. `name` = id; `description` = a one-line genre summary derived from `meta.json.genre`.

If `design-systems/<id>/gallery.html` is absent, fail this workflow and surface to user: the DS library node is incomplete. Workflow 0 owes the file. Don't try to scrape feature pages - that's the old broken path the DS-as-library architecture exists to prevent.

## Format (unchanged)

Follows [google-labs-code/design.md](https://github.com/google-labs-code/design.md): YAML frontmatter (normative) + prose (rationale). Sections in this order; any can be omitted:

```
---
name: <ds-id>
description: <one-line genre summary>
colors: { token-name: "#HEX" }
typography: { token-name: { fontFamily, fontSize, fontWeight, … } }
rounded: { sm|md|lg: <dim> }
spacing: { token-name: <dim> }
components: { name: { variants: "…" } }
---

## Overview
## Colors
## Typography
## Layout
## Elevation & Depth
## Shapes
## Components
## Do's and Don'ts
```

## Rules

- OKLCH → sRGB hex for the YAML `colors` map (spec demands hex). Keep OKLCH inline in the prose section.
- `name` = `meta.json.id`.
- `description` = a one-line summary of `meta.json.genre`. Fallback: the genre verbatim.
- **`components` YAML** is generated by walking `gallery.html`'s `<section class="ds-section" id="<slug>">` blocks and listing the variants present (every `.ds-sample` within a section contributes variants identified by their class composition). Don't double-author primitive lists in DESIGN.md - `gallery.html` is canonical.
- **Component prose** (the `## Components` section in DESIGN.md) describes intent and usage; the markup lives in `gallery.html`. The prose should reference the gallery as the rendered source of truth: "See `design-systems/<id>/gallery.html` for the rendered gallery; this section describes intent only."

## Drift check (gate before write)

Before writing `DESIGN.md`:

1. Cross-check `gallery.html` primitive sections vs the runtime mirror's `D.primitives[]` in `editor/design-systems/<id>.js`. Every section should have a matching primitive entry. Mismatch → fail the workflow; Workflow 0 (or 6b) owes the missing section / entry.
2. Cross-check `:root` tokens vs `D.tokens.*`. Drift → re-run Workflow 0's runtime-mirror step.

Both checks are cheap and prevent DESIGN.md from documenting a phantom design system that doesn't render.

## Where DESIGN.md is read from

- **DS library node header** in the editor - toggle next to the kitchen-sink view.
- **Subagent 1** when generating feature pages - reads `DESIGN.md` for prose context but consumes the DS as a vocabulary through `styles.css` + `gallery.html` directly. `DESIGN.md` is reference material, not the authoritative source.
- **External tools** (e.g. `google-labs-code` consumers) - the YAML frontmatter is machine-readable.

## What this workflow does NOT touch

- **Branch data files.** `editor/data.js` is not rewritten by this workflow. `meta.dsRef` already points at the DS; that reference is unchanged.
- **`source/`.** Feature pages don't reference `DESIGN.md` directly.
- **Project root `DESIGN.md`.** That file no longer exists in the DS-as-library architecture - `DESIGN.md` lives inside each DS folder.

## Self-audit

- [ ] Both inputs exist (`styles.css`, `gallery.html`, `meta.json`) for `design-systems/<id>/`.
- [ ] YAML frontmatter has `name = meta.json.id`, `description` derived from `meta.json.genre`.
- [ ] `colors` map has hex values (OKLCH → sRGB conversion); OKLCH retained in prose.
- [ ] `components` YAML enumerates every `<section class="ds-section">` from `gallery.html`.
- [ ] Drift checks (gallery sections vs runtime mirror primitives; `:root` tokens vs runtime mirror tokens) both pass.
- [ ] Prose references `gallery.html` as the rendered source of truth; doesn't duplicate variant lists.
- [ ] Written to `design-systems/<id>/DESIGN.md` - not project root, not `source/`.
