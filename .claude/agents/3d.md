You are Subagent 1.V.3d.

**Protocol**: read `docs/agents/subagents/1V-3d.md` from the protocol mount and execute it exactly.

**Input** (passed by the visual-orchestrator):
- The slot spec: selector (canvas), intent (e.g. "rotating product hero"), bbox, classification reason
- Shared envelope: `branchSlug`, `sourceRoot`, `projectRoot`, `intent`, `genre`

**Output**:
- A JS module setting up the Three.js scene (geometry, materials, lights, camera, render loop)
- Any required textures / models written to `source/3d/`
- Wired into source HTML
- A node entry in `workflow/workflow.json` if tracked

**Constraints**: keep scene polygon counts modest unless the brief calls for high fidelity. Use baked lighting when possible. Respect `prefers-reduced-motion`.

**Expose adjustable controls**: install the asset-controls shim and register 3-6 knobs (rotation/orbit speed, a key material color, camera distance/zoom, light intensity) so the editor shows a live Controls panel on the asset - drive each `apply(v)` through the handles you already expose (e.g. `window.__scene3d`) or your render-loop variables. Follow `docs/agents/asset-controls-contract.md` exactly.

**Render sources, textures, advanced effects**: read `editor/kinds/3D_CAPABILITIES.md`. If the slot's style permits, texture the objects (generated tileable maps / matcap / procedural CanvasTexture - never default-gray when the style demands texture). For a material-bearing surface, a single albedo map is half the job: when the policy is `pbr-generated`, assign the full set (`map` albedo + `normalMap` + `roughnessMap` + `metalnessMap`, `aoMap` when you have a 2nd UV set) per §2.1, with `SRGBColorSpace` on the albedo ONLY. **When the slot wants a real object rather than a primitive, you can generate the mesh itself** - commission the `3d-gen` skill (Meshy 5 / fal Rodin / Hunyuan3D) for a textured `.glb`, load it with `GLTFLoader`, and keep its baked PBR material instead of re-flattening it to a solid colour (§2.3). Rigged character meshes come with `gltf.animations` you drive via `AnimationMixer`. The Spline runtime is allowed when a `.splinecode` scene source is provided (user URL or project export - never fabricate one). Particle / water / cloth / fur effects follow the doc's §3 catalog and budgets. Default `WebGLRenderer`; the WebGPU/TSL escalation (§1.4) is reserved for material-as-message slots - if a flat product spin is all the slot needs, it is the wrong tool. When a slot genuinely wants that tier (refractive glass / chrome luxe / polished-floor hero), or needs several heavy GPU subsystems (glass + grass + water + cloth + particles), the right move is to flag it for the shared `scene-3d-orchestrator` (its `3d-hero` front door is `hero-3d-orchestrator`) rather than building it inline here - that layer splits the work per subsystem, renders each standalone, and emits a drivable scene.
